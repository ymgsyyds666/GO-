## 2. HTTP 与 REST 设计（D15）

### 2.1 必须记牢的

| 项 | 要点 |
|---|---|
| 方法语义 | GET 查询（幂等）、POST 创建、PUT 全量更新（幂等）、PATCH 部分更新、DELETE 删除（幂等） |
| 状态码 | 200/201/204、400 参数错、401 未认证、403 无权限、404、409 冲突、422 校验失败、429 限流、500 服务错、502/504 网关/超时 |
| 幂等 | GET/PUT/DELETE 天然幂等；POST 需要幂等键 |
| 超时 | 客户端超时 < 网关超时 < 服务端处理超时，逐层收敛 |
| 分页 | `?page=1&size=20` 或游标 `?cursor=xxx`（大数据量用游标） |

### 2.2 接口设计规范（团队可直接抄）

```json
// 统一响应体
{ "code": 0, "message": "ok", "data": { ... }, "trace_id": "abc" }

// 错误
{ "code": 40001, "message": "参数校验失败", "data": null, "trace_id": "abc" }

// 列表
{ "code": 0, "data": { "list": [], "total": 100, "page": 1, "size": 20 } }
```

约定：

- `code=0` 成功；业务错误码分段（1xxxx 用户、2xxxx 订单…），HTTP 状态码仍用标准语义。
- 时间统一 RFC3339（`2026-11-18T10:00:00+08:00`），存 UTC。
- ID 用字符串返回（防 JS 精度丢失）：`"id": "1234567890123456789"`。
- 版本：`/api/v1/...`；破坏性变更才升 v2。

### 2.3 原生 net/http 手写一遍（不许跳）

Go 1.22 起 `ServeMux` 支持方法和路径参数：

```go
mux := http.NewServeMux()
mux.HandleFunc("GET /users/{id}", func(w http.ResponseWriter, r *http.Request) {
	id := r.PathValue("id")
	writeJSON(w, 200, map[string]string{"id": id})
})
```

中间件就是 `func(http.Handler) http.Handler`：

```go
func Logging(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		start := time.Now()
		next.ServeHTTP(w, r)
		log.Printf("%s %s %v", r.Method, r.URL.Path, time.Since(start))
	})
}
```

生产级 Server 配置（**超时不全配 = 慢连接拖死服务**）：

```go
srv := &http.Server{
	Addr:              ":8080",
	Handler:           mux,
	ReadHeaderTimeout: 5 * time.Second,   // 防 Slowloris
	ReadTimeout:       15 * time.Second,
	WriteTimeout:      30 * time.Second,
	IdleTimeout:       60 * time.Second,
	MaxHeaderBytes:    1 << 20,
}

go srv.ListenAndServe()

// 优雅关闭：先停止接收新请求，再等存量请求结束
quit := make(chan os.Signal, 1)
signal.Notify(quit, syscall.SIGINT, syscall.SIGTERM)
<-quit

ctx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
defer cancel()
if err := srv.Shutdown(ctx); err != nil {
	log.Printf("shutdown: %v", err)
}
```

> 面试常问：`Shutdown` 会等待活跃连接处理完；若有长连接（WebSocket）需单独关闭。

## 3. 框架选型（D16）

### 3.1 横向对比

| 框架 | 底层 | 定位 | 性能 | 学习曲线 | 生态 | 适合 |
|---|---|---|---|---|---|---|
| **Gin** | net/http | 最流行的 Web 框架 | 高 | 低 | 极大 | 学习、API 服务、快速交付 |
| **Echo** | net/http | Gin 的"更整洁版" | 高 | 低 | 大 | 喜欢清晰 API 的团队 |
| **Fiber** | fasthttp | 高性能 Express 风格 | 很高 | 低 | 中 | 极致吞吐、不依赖 net/http 生态 |
| **Chi** | net/http | 极简路由，标准库风格 | 高 | 低 | 中 | 微服务、想要标准库兼容 |
| **Hertz** | netpoll | 字节开源，高性能 | 很高 | 中 | 中 | 高并发网关/中台 |
| **go-zero** | 自研 | 微服务全家桶 + 代码生成 | 高 | 中 | 大（国内） | 业务快速落地、完整治理 |
| **Kratos** | gRPC/HTTP | B 站开源，云原生 | 高 | 中高 | 大 | 中大型微服务、DDD |
| **Kitex** | netpoll | 字节 RPC 框架 | 很高 | 中 | 中 | 纯 RPC 场景 |

### 3.2 给你的路线（30 天内）

```
Gin（D16，理解 HTTP 与中间件）
  └─→ go-zero 或 Kratos（D17–D21 选一个，跑通完整微服务）
        └─→ 读一个框架的源码核心（路由树 / 拦截器链）
```

**选哪个？**

- 公司已有技术栈 → 跟公司走。
- 想快速做业务、国内岗位多 → **go-zero**（`goctl` 生成 api/rpc/model，开发效率极高）。
- 想进大厂/云原生团队 → **Kratos**（protobuf 优先、wire 依赖注入、可插拔治理）。
- 先把 Gin 吃透，其余都是"路由 + 中间件 + 依赖注入"的不同组合。

## 4. Gin 实战：一个可交付的 API 服务（D16）

### 4.1 项目结构

```
shorturl/
├── cmd/server/main.go          # 只做装配与启动
├── internal/
│   ├── config/config.go        # 配置结构体
│   ├── handler/                # HTTP 层：参数校验、响应
│   ├── service/                # 业务逻辑：编排、事务边界
│   ├── repository/             # 数据访问：SQL/Redis
│   ├── middleware/             # 中间件
│   └── model/                  # 领域模型/DTO
├── pkg/                        # 可复用工具（resp、errcode、logger）
├── configs/config.yaml
└── go.mod
```

依赖方向：`handler → service → repository`，**反向不允许**。接口定义在消费者一侧。

### 4.2 入口 + 中间件 + 优雅关闭

```go
// cmd/server/main.go
func main() {
	cfg := config.MustLoad("configs/config.yaml")

	r := gin.New()
	r.Use(gin.Recovery(), middleware.TraceID(), middleware.AccessLog(), middleware.CORS())

	v1 := r.Group("/api/v1")
	{
		v1.GET("/healthz", func(c *gin.Context) { c.String(200, "ok") })
		v1.POST("/links", handler.CreateLink)
		v1.GET("/links/:code", handler.Redirect)
	}

	srv := &http.Server{
		Addr:              cfg.Addr,
		Handler:           r,
		ReadHeaderTimeout: 5 * time.Second,
		ReadTimeout:       15 * time.Second,
		WriteTimeout:      30 * time.Second,
		IdleTimeout:       60 * time.Second,
	}

	go func() {
		if err := srv.ListenAndServe(); err != nil && !errors.Is(err, http.ErrServerClosed) {
			log.Fatalf("listen: %v", err)
		}
	}()

	quit := make(chan os.Signal, 1)
	signal.Notify(quit, syscall.SIGINT, syscall.SIGTERM)
	<-quit

	ctx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
	defer cancel()
	if err := srv.Shutdown(ctx); err != nil {
		log.Printf("forced shutdown: %v", err)
	}
	log.Println("server exited")
}
```

### 4.3 参数绑定与校验

```go
type CreateLinkReq struct {
	URL      string `json:"url" binding:"required,url"`
	ExpireAt int64  `json:"expire_at" binding:"omitempty,gt=0"`
}

func CreateLink(c *gin.Context) {
	var req CreateLinkReq
	if err := c.ShouldBindJSON(&req); err != nil {
		resp.Error(c, errcode.InvalidParam, err.Error())
		return
	}
	link, err := svc.Create(c.Request.Context(), req.URL)
	if err != nil {
		resp.Error(c, errcode.From(err), "")
		return
	}
	resp.OK(c, link)
}
```

### 4.4 中间件：TraceID + 访问日志 + 恢复

```go
const traceKey = "trace_id"

func TraceID() gin.HandlerFunc {
	return func(c *gin.Context) {
		id := c.GetHeader("X-Trace-ID")
		if id == "" {
			id = uuid.NewString()
		}
		c.Set(traceKey, id)
		c.Header("X-Trace-ID", id)
		c.Request = c.Request.WithContext(context.WithValue(c.Request.Context(), ctxKey{}, id))
		c.Next()
	}
}

func AccessLog() gin.HandlerFunc {
	return func(c *gin.Context) {
		start := time.Now()
		c.Next()
		slog.Info("access",
			slog.String("method", c.Request.Method),
			slog.String("path", c.Request.URL.Path),
			slog.Int("status", c.Writer.Status()),
			slog.Duration("cost", time.Since(start)),
			slog.String("trace_id", c.GetString(traceKey)),
		)
	}
}

func Recover() gin.HandlerFunc {
	return func(c *gin.Context) {
		defer func() {
			if rec := recover(); rec != nil {
				slog.Error("panic", "err", rec, "stack", string(debug.Stack()))
				resp.Error(c, errcode.Internal, "")
				c.Abort()
			}
		}()
		c.Next()
	}
}
```

### 4.5 统一响应与错误码

```go
package resp

type Body struct {
	Code    int    `json:"code"`
	Message string `json:"message"`
	Data    any    `json:"data,omitempty"`
	TraceID string `json:"trace_id,omitempty"`
}

func OK(c *gin.Context, data any) {
	c.JSON(200, Body{Code: 0, Message: "ok", Data: data})
}

func Error(c *gin.Context, e errcode.Error, detail string) {
	// 5xx 记日志，4xx 不记（避免日志污染）
	if e.HTTP >= 500 {
		slog.Error("request failed", "code", e.Code, "detail", detail)
	}
	c.JSON(e.HTTP, Body{Code: e.Code, Message: e.Msg})
}
```

```go
package errcode

type Error struct {
	Code int
	Msg  string
	HTTP int
}

var (
	InvalidParam = Error{40001, "参数错误", 400}
	NotFound     = Error{40401, "资源不存在", 404}
	Internal     = Error{50000, "服务内部错误", 500}
)
```

### 4.6 JWT 鉴权中间件

```go
func Auth(secret []byte) gin.HandlerFunc {
	return func(c *gin.Context) {
		tokenStr := strings.TrimPrefix(c.GetHeader("Authorization"), "Bearer ")
		if tokenStr == "" {
			c.AbortWithStatusJSON(401, gin.H{"code": 40100, "message": "unauthorized"})
			return
		}
		tok, err := jwt.Parse(tokenStr, func(t *jwt.Token) (any, error) {
			if _, ok := t.Method.(*jwt.SigningMethodHMAC); !ok {
				return nil, fmt.Errorf("unexpected signing method")
			}
			return secret, nil
		})
		if err != nil || !tok.Valid {
			c.AbortWithStatusJSON(401, gin.H{"code": 40100, "message": "invalid token"})
			return
		}
		claims := tok.Claims.(jwt.MapClaims)
		c.Set("uid", claims["sub"])
		c.Next()
	}
}
```

> 生产建议：JWT 只放 `sub`/`exp`/`jti`，权限查缓存；配合 refresh token；密钥从 KMS/环境变量读取。

## 5. go-zero / Kratos 快速上手（D17–D21 选一个）

### 5.1 go-zero：约定优于配置

```
shorturl/
├── api/shorturl.api          # 声明式 API 定义
├── internal/
│   ├── config/
│   ├── handler/              # goctl 生成
│   ├── logic/                # 业务逻辑（你写这里）
│   ├── svc/                  # ServiceContext：依赖注入容器
│   └── types/types.go        # 生成的请求/响应结构
├── shorturl.go               # 入口
└── etc/shorturl.yaml
```

```go
// api/shorturl.api
type CreateReq {
	Url string `json:"url" validate:"required,url"`
}
type CreateResp {
	Code string `json:"code"`
}

@server(
	prefix: /api/v1
	group:  link
)
service shorturl-api {
	@handler CreateLink
	post /links (CreateReq) returns (CreateResp)
}
```

```bash
goctl api go -api api/shorturl.api -dir .    # 生成骨架
goctl model mysql datasource -url="$DSN" -table=links -dir=internal/model   # 生成带缓存的 model
```

go-zero 的杀手锏：**model 层自带缓存逻辑**（`FindOne` 自动先查 Redis 再查 DB，并防击穿），以及内置 `breaker`/`limit`/`timeout` 治理能力。

### 5.2 Kratos：protobuf 优先 + wire 注入

```
shorturl/
├── api/link/v1/link.proto
├── internal/
│   ├── biz/          # 业务用例（DDD 的 domain/application 合并）
│   ├── data/         # 数据访问，实现 biz 定义的 repo 接口
│   ├── service/      # 传输层适配（HTTP/gRPC 共用）
│   ├── server/       # http/grpc server 装配
│   └── conf/
├── cmd/shorturl/main.go
└── third_party/
```

```bash
kratos new shorturl
kratos proto add api/link/v1/link.proto
kratos proto client api/link/v1/link.proto    # 生成 pb + grpc + http
kratos proto server api/link/v1/link.proto -t internal/service
```

Kratos 的关键概念：`biz` 定义 `Repo` 接口，`data` 实现它，`wire` 生成装配代码。**依赖倒置**做得最彻底，适合长期演进的中大型项目。

### 5.3 怎么选（决策表）

| 你的情况 | 选择 |
|---|---|
| 团队 3~10 人，要 2 周上线业务 | go-zero |
| 公司已有 K8s + 服务网格 + 多语言 | Kratos |
| 只是单体 API，不想背框架 | Gin + 自己分层 |
| 极致性能网关 | Hertz / Fiber |

## 7. MySQL：连接池、事务、索引（D17）

### 7.1 连接池参数（必背）

```go
db, err := sql.Open("mysql", dsn)
db.SetMaxOpenConns(100)                 // 最大连接数：DB 侧 max_connections 的 1/实例数
db.SetMaxIdleConns(20)                  // 空闲连接，太小会频繁建连
db.SetConnMaxLifetime(30 * time.Minute) // 必须 < MySQL wait_timeout，防用到被服务端断开的连接
db.SetConnMaxIdleTime(5 * time.Minute)
```

> 压测时如果 `wait` 时间长，先看 `db.Stats()`：`WaitCount`、`WaitDuration`、`InUse`。

### 7.2 sqlx 写法（比 GORM 更可控）

```go
type LinkRepo struct{ db *sqlx.DB }

func (r *LinkRepo) GetByCode(ctx context.Context, code string) (*Link, error) {
	var l Link
	err := r.db.GetContext(ctx, &l,
		`SELECT id, code, url, expire_at FROM links WHERE code = ?`, code)
	if errors.Is(err, sql.ErrNoRows) {
		return nil, ErrNotFound
	}
	return &l, err
}

func (r *LinkRepo) ListByUser(ctx context.Context, uid int64, offset, limit int) ([]Link, error) {
	var list []Link
	err := r.db.SelectContext(ctx, &list,
		`SELECT id, code, url FROM links WHERE user_id = ? ORDER BY id DESC LIMIT ? OFFSET ?`,
		uid, limit, offset)
	return list, err
}
```

### 7.3 GORM 写法（CRUD 快，注意性能陷阱）

```go
type Link struct {
	ID       int64     `gorm:"primaryKey"`
	Code     string    `gorm:"size:16;uniqueIndex"`
	URL      string    `gorm:"size:2048;not null"`
	UserID   int64     `gorm:"index"`
	CreatedAt time.Time
}

// 事务
err := db.WithContext(ctx).Transaction(func(tx *gorm.DB) error {
	if err := tx.Create(&link).Error; err != nil { return err }
	return tx.Model(&User{}).Where("id = ?", uid).
		UpdateColumn("link_count", gorm.Expr("link_count + 1")).Error
})

// 分页 + 预加载（避免 N+1）
var users []User
db.WithContext(ctx).Preload("Orders").Limit(20).Offset(0).Find(&users)

// 批量插入
db.CreateInBatches(&links, 500)
```

GORM 坑：`Find` 传空切片会查全表？不会，但没有条件时慎用；`Save` 是全字段更新；软删除的 `deleted_at` 索引要建。

### 7.4 索引与慢查询

```sql
EXPLAIN SELECT * FROM links WHERE code = 'abc';
-- 关注 type（range/ref/const 好，ALL 差）、key、rows、Extra（Using filesort 差）

-- 联合索引最左前缀：(user_id, created_at) 能服务 WHERE user_id=? ORDER BY created_at
-- 深分页优化：LIMIT 100000,20 → 用游标
SELECT * FROM links WHERE id > 100000 ORDER BY id LIMIT 20;
```

### 7.5 迁移

```bash
# golang-migrate
migrate create -ext sql -dir migrations -seq create_links
migrate -path migrations -database "$DSN" up
```

原则：**迁移脚本只增不改**；生产变更走"扩展-切换-收缩"三步（加列 → 双写 → 删旧列）。

## 8. Redis 与缓存设计（D18）

### 8.1 基础用法

```go
rdb := redis.NewClient(&redis.Options{
	Addr:         cfg.Addr,
	Password:     cfg.Password,
	PoolSize:     100,
	MinIdleConns: 10,
	DialTimeout:  2 * time.Second,
	ReadTimeout:  1 * time.Second,
	WriteTimeout: 1 * time.Second,
})

ctx, cancel := context.WithTimeout(ctx, 500*time.Millisecond)
defer cancel()

val, err := rdb.Get(ctx, key).Result()
if errors.Is(err, redis.Nil) { /* 不存在 */ }
rdb.Set(ctx, key, val, 10*time.Minute)
rdb.Incr(ctx, "counter")
rdb.HSet(ctx, "user:1", "name", "tom")
rdb.Expire(ctx, key, time.Hour)
```

### 8.2 缓存三兄弟（必须能画图讲）

| 问题 | 现象 | 方案 |
|---|---|---|
| **穿透** | 查不存在的数据，每次都打 DB | 缓存空值（短 TTL）+ 布隆过滤器 + 参数校验 |
| **击穿** | 热点 key 过期瞬间大量请求打到 DB | 逻辑过期 / 互斥锁重建 / singleflight |
| **雪崩** | 大量 key 同时过期或 Redis 宕机 | TTL 加随机抖动 + 多级缓存 + 熔断降级 |

```go
// 缓存空值防穿透
func (r *Repo) Get(ctx context.Context, id int64) (*User, error) {
	key := fmt.Sprintf("user:%d", id)
	if v, err := r.rdb.Get(ctx, key).Bytes(); err == nil {
		if string(v) == "null" { return nil, ErrNotFound }
		var u User
		json.Unmarshal(v, &u)
		return &u, nil
	}

	u, err := r.db.GetUser(ctx, id)
	if errors.Is(err, sql.ErrNoRows) {
		r.rdb.Set(ctx, key, "null", time.Minute)   // 短 TTL 防穿透
		return nil, ErrNotFound
	}
	if err != nil { return nil, err }

	b, _ := json.Marshal(u)
	r.rdb.Set(ctx, key, b, 10*time.Minute+time.Duration(rand.IntN(60))*time.Second)
	return u, nil
}
```

### 8.3 缓存一致性：先更新 DB 再删缓存

```
写：更新 DB → 删除缓存（延迟双删：删 → 500ms → 再删）
读：读缓存 → miss → 读 DB → 回填
```

极端不一致窗口用 **binlog 订阅（canal）异步删缓存** 兜底。别追求强一致，用 TTL 最终一致即可。

### 8.4 分布式锁（Redis）

```go
func Lock(ctx context.Context, rdb *redis.Client, key, token string, ttl time.Duration) (bool, error) {
	return rdb.SetNX(ctx, key, token, ttl).Result()
}

// 解锁必须校验 token + Lua 保证原子
var unlockScript = redis.NewScript(`
if redis.call("get", KEYS[1]) == ARGV[1] then
  return redis.call("del", KEYS[1])
else
  return 0
end`)

func Unlock(ctx context.Context, rdb *redis.Client, key, token string) error {
	return unlockScript.Run(ctx, rdb, []string{key}, token).Err()
}
```

生产用 `github.com/redis/go-redis/extra/redsync`（带自动续期），或直接用 etcd 的 lease 锁。

> 分布式锁不能保证 100% 安全（GC 停顿、时钟漂移），涉及资金的操作要用**数据库唯一约束/状态机**做最终兜底。

### 8.5 本地缓存

```go
// 读多写少、容忍短暂不一致：bigcache / ristretto / freecache
cache, _ := bigcache.New(context.Background(), bigcache.DefaultConfig(10*time.Minute))
cache.Set("key", []byte("val"))
val, _ := cache.Get("key")
```

多级缓存：`本地(1s TTL) → Redis → DB`，本地缓存用来扛热点 key。

## 9. 消息队列（D19）

### 9.1 选型

| MQ | 特点 | Go 客户端 | 适用 |
|---|---|---|---|
| Kafka | 高吞吐、持久化、生态最好 | `franz-go`（推荐）、`segmentio/kafka-go` | 日志、事件流、大数据 |
| NATS JetStream | 轻量、低延迟、部署简单 | `nats.go` | 内部事件、轻量任务 |
| RabbitMQ | 路由灵活、可靠投递 | `amqp091-go` | 业务解耦、任务队列 |
| RocketMQ | 国内电商常用、事务消息 | `rocketmq-client-go` | 交易、订单 |
| Redis Stream | 无需新组件 | go-redis | 小规模、临时方案 |

### 9.2 Kafka 生产/消费（franz-go）

```go
// 生产
client, _ := kgo.NewClient(kgo.SeedBrokers("localhost:9092"))
defer client.Close()

client.Produce(ctx, &kgo.Record{
	Topic: "order.created",
	Key:   []byte(orderID),          // 同 key 保证分区有序
	Value: payload,
}, func(r *kgo.Record, err error) {
	if err != nil { log.Printf("produce: %v", err) }
})

// 消费
consumer, _ := kgo.NewClient(
	kgo.SeedBrokers("localhost:9092"),
	kgo.ConsumerGroup("order-worker"),
	kgo.ConsumeTopics("order.created"),
)
defer consumer.Close()

for {
	fetches := consumer.PollFetches(ctx)
	fetches.EachError(func(t string, p int32, err error) { log.Printf("fetch: %v", err) })
	fetches.EachRecord(func(r *kgo.Record) {
		if err := handle(ctx, r.Value); err != nil {
			// 幂等 + 重试 + 死信
		}
	})
}
```

### 9.3 消息可靠性三板斧

1. **至少一次 + 消费幂等**：用业务唯一键（订单号）+ 去重表/Redis SETNX，别指望 exactly-once。
2. **重试 + 死信**：本地重试 3 次（指数退避）→ 进死信 topic → 人工/定时补偿。
3. **顺序**：同 key 同分区；不要用全局顺序（性能灾难）。

## 10. gRPC 与 protobuf（D19）

### 10.1 proto 定义

```proto
syntax = "proto3";

package user.v1;
option go_package = "example.com/shorturl/api/user/v1;userv1";

service UserService {
  rpc GetUser(GetUserRequest) returns (GetUserResponse);
  rpc ListUsers(ListUsersRequest) returns (stream User);   // 服务端流
}

message GetUserRequest  { int64 id = 1; }
message GetUserResponse { int64 id = 1; string name = 2; }
message ListUsersRequest { int32 page_size = 1; }
message User { int64 id = 1; string name = 2; }
```

### 10.2 服务端

```go
lis, err := net.Listen("tcp", ":9000")
if err != nil { log.Fatal(err) }

s := grpc.NewServer(
	grpc.UnaryInterceptor(otelgrpc.UnaryServerInterceptor()),
```

### 10.3 客户端（必须带超时）

```go
conn, err := grpc.NewClient("127.0.0.1:9000",
	grpc.WithTransportCredentials(insecure.NewCredentials()),
)
defer conn.Close()

cli := userv1.NewUserServiceClient(conn)
ctx, cancel := context.WithTimeout(ctx, 2*time.Second)
```

### 10.4 生产要点

- **错误码**：用 `status.Error(codes.InvalidArgument, "...")`，别返回裸 error。
- **拦截器**：统一做 trace、日志、恢复、超时、鉴权、限流。
- **负载均衡**：客户端 LB（round_robin）+ 服务发现（etcd/consul/nacos/K8s DNS）。
- **压缩**：大 payload 开 gzip；小请求别开（浪费 CPU）。
- **连接复用**：一个进程一个 `*grpc.ClientConn`，不要每次请求新建。

### 11.2 指标：Prometheus

```go
var (
	httpRequests = prometheus.NewCounterVec(
		prometheus.CounterOpts{Name: "http_requests_total", Help: "total requests"},
		[]string{"method", "path", "status"},
	)
	httpDuration = prometheus.NewHistogramVec(
		prometheus.HistogramOpts{
			Name:    "http_request_duration_seconds",
			Buckets: []float64{.005, .01, .025, .05, .1, .25, .5, 1, 2.5},
		},
		[]string{"method", "path"},
	)
)

func init() {
	prometheus.MustRegister(httpRequests, httpDuration)
}

func Metrics() gin.HandlerFunc {
	return func(c *gin.Context) {
		start := time.Now()
		c.Next()
		httpRequests.WithLabelValues(c.Request.Method, c.FullPath(), strconv.Itoa(c.Writer.Status())).Inc()
		httpDuration.WithLabelValues(c.Request.Method, c.FullPath()).Observe(time.Since(start).Seconds())
	}
}

r.GET("/metrics", gin.WrapH(promhttp.Handler()))
```

> `c.FullPath()` 而不是 `c.Request.URL.Path`，否则 label 爆炸。

## 12. 安全清单

- [ ] 密码用 `bcrypt`（cost 10~12）或 argon2id，**绝不明文/MD5**
- [ ] 所有 SQL 用参数化查询，禁止字符串拼接
- [ ] JWT：短过期 + refresh token + 黑名单（登出）
- [ ] 越权：每个查询都带 `user_id` 条件，别只靠前端
- [ ] 限流：IP + 用户双维度，登录接口更严
- [ ] 敏感字段日志脱敏（手机号、身份证、token）

- [ ] HTTP 安全头：HSTS、X-Content-Type-Options
