## 1. 先建立正确的学习姿势

Go 的语法一周就能过完，难的是**用 Go 的方式思考**。三条原则：

1. **Go 只有一种循环（for），一种"继承"（组合），一种错误处理（返回值）。** 遇到问题先想"标准库怎么做"，而不是"Java/Python 怎么做"。
2. **先写能跑的，再写好看的。** 接口、分层、泛型都是后话。
3. **每学一个语法点，就去 LeetCode 用它解一道题。** 语法只有被"用过"才会变成肌肉记忆。

推荐顺序（也是本文顺序）：

```
工具链 → 变量/类型 → 字符串 → 切片 → map → 流程控制 → 函数
→ 指针/结构体/方法 → 接口 → 错误 → 泛型 → 包管理 → 标准库 → 测试
```

## 2. 程序结构与工具链（D1）

### 2.1 最小程序

```go
// main.go
package main

import "fmt"

func main() {
	fmt.Println("hello, gopher")
}
```

```bash
go mod init example.com/hello   # 初始化模块，生成 go.mod
go run .                        # 编译并运行
go build -o hello .             # 产出可执行文件
go vet ./...                    # 静态检查
gofmt -w .                      # 格式化（IDE 保存时自动做）
```

### 2.2 `go.mod` 每一行都要能解释

```
module example.com/hello        // 模块路径：别人 import 你时的前缀
go 1.25                         // 语言版本（影响语法特性可用性）
require github.com/gin-gonic/gin v1.10.0
```

常用命令：

| 命令 | 作用 | 什么时候用 |
|---|---|---|
| `go mod tidy` | 增删依赖、对齐 go.sum | 每次改完 import |
| `go mod download` | 下载到本地缓存 | CI / 换机器 |
| `go get pkg@v1.2.3` | 添加/升级依赖 | 加库 |
| `go list -m all` | 查看依赖树 | 排查版本冲突 |
| `go work init` | 多模块工作区 | 一个仓库多个服务 |
| `go install pkg@latest` | 安装命令行工具 | 装 lint/dlv |

> **GOPROXY 必配**：`go env -w GOPROXY=https://goproxy.cn,direct`，否则拉包会卡死。

### 2.3 包与可见性

- 大写字母开头 = 导出（public），小写 = 包内私有。**没有 `private/public` 关键字。**
- 一个目录 = 一个包；`package main` 且含 `func main()` 才能产出可执行文件。
- `internal/` 目录下的包，只能被其父目录及以内的代码 import —— 这是 Go 的"模块私有"机制，工程里必用。

```
myservice/
├── cmd/api/main.go          # 入口，只做装配
├── internal/
│   ├── handler/             # 只能被 myservice 内部引用
│   ├── service/
│   └── repo/
├── pkg/                     # 允许外部引用的公共库
└── go.mod
```

## 3. 变量、常量与类型（D1）

### 3.1 声明方式

```go
var a int            // 零值 0
var b = 10           // 类型推断
c := "short"         // 短声明，只能在函数内
var (
	d int
	e string
)
const Pi = 3.14
const (
	StatusOK = 200
	StatusNotFound = 404
)
```

### 3.2 零值 —— Go 没有"未初始化"

| 类型 | 零值 |
|---|---|
| 数值 | `0` |
| string | `""` |
| bool | `false` |
| 指针 / slice / map / chan / func / interface | `nil` |
| struct | 各字段零值 |

```go
var s []int          // nil slice：len=0, cap=0，可直接 append
var m map[string]int // nil map：可读，写入会 panic！
m["a"] = 1           // panic: assignment to entry in nil map
```

> **新手第一个大坑**：`map` 和 `channel` 必须 `make` 才能写。

### 3.3 常量与 `iota`

```go
type Weekday int

const (
	Sunday Weekday = iota // 0
	Monday                // 1
	Tuesday               // 2
)

// 位标志：常见于权限、选项
type Flag uint8

const (
	FlagA Flag = 1 << iota // 1
	FlagB                  // 2
	FlagC                  // 4
)

var f Flag = FlagA | FlagC      // 5
fmt.Println(f&FlagC != 0)       // true：判断是否包含 FlagC
fmt.Println(f^(FlagA|FlagC))    // 0：去掉 A、C 后为空
```

`iota` 在每个 `const` 块内从 0 开始，每行 +1，可参与表达式。

### 3.4 类型转换没有隐式

```go
var i int = 10
var f float64 = float64(i)   // 必须显式
var u uint = uint(i)
// var x int = f             // 编译错误

// 注意溢出：int8 装 128 会回绕
var x int8 = 127
x++                          // -128（运行时不报错！）
```

### 3.5 值类型 vs 引用类型（语义）

Go 全是**值传递**。所谓"引用类型"（slice/map/chan/interface/指针）传递的是包含指针的小结构体，所以改内容能影响原值，但重新赋值不会。

```go
func modifySlice(s []int) {
	s[0] = 99       // 影响原切片：底层数组共享
	s = append(s, 1) // 不影响原切片：只改了本地 header
}

func modifyMap(m map[string]int) {
	m["k"] = 1      // 影响原 map：header 里是指针
}
```

> 面试高频：**"Go 是值传递还是引用传递？"** —— 值传递。map/slice 之所以"像引用"，是因为内部持有指针。

## 4. 字符串与字符（D2）

Go 的 string 是**不可变的字节序列**（UTF-8 编码）。

```go
s := "Go语言"
fmt.Println(len(s))            // 8：字节数（"语言"各 3 字节）
fmt.Println(utf8.RuneCountInString(s)) // 4：字符数

for i, r := range s {          // i 是字节偏移，r 是 rune
	fmt.Printf("%d:%c ", i, r) // 0:G 1:o 2:语 5:言
}

b := []byte(s)                 // 转字节切片（会拷贝）
r := []rune(s)                 // 转 rune 切片（按字符）
fmt.Println(string(r[2]))      // 语
```

三个高频 API 家族：

```go
strings.Contains / HasPrefix / HasSuffix / Index / Split / Join
strings.TrimSpace / Trim / ReplaceAll / ToUpper / ToLower / Repeat
strings.Builder  // 高频拼接，零拷贝增长，必须用它而不是 +=

var sb strings.Builder
for i := 0; i < 3; i++ {
	sb.WriteString("go")
}
fmt.Println(sb.String()) // gogo
```

性能对比（10000 次拼接）：`+=` 约 200ms（O(n²) 拷贝），`strings.Builder` 约 0.2ms。

> **陷阱**：`for i := 0; i < len(s); i++` 按字节遍历，遇到中文会拆坏；要按字符遍历用 `range` 或 `[]rune(s)`。

## 5. 数组与切片（D3）

### 5.1 数组：值类型，长度是类型的一部分

```go
var a [3]int          // 长度固定
b := [3]int{1, 2, 3}
c := [...]int{1, 2, 3} // 编译器数长度
d := a                // 整体拷贝！
d[0] = 100
fmt.Println(a[0], d[0]) // 0 100
```

### 5.2 切片：真正的日常

```go
s := make([]int, 3, 5)   // len=3, cap=5
s = append(s, 1)         // len=4, cap=5
s = append(s, 2, 3)      // 超容量，触发扩容，cap 变化
```

**必须能画出这个结构**：

```
slice header:  { ptr → 底层数组, len, cap }
```

```go
arr := [5]int{1, 2, 3, 4, 5}
s1 := arr[1:3]        // len=2 cap=4（cap 从起点算到数组末尾）
s1[0] = 99
fmt.Println(arr)      // [1 99 3 4 5] —— 共享底层数组

s2 := s1[0:4]         // 越过 len 但不超过 cap 是合法的
```

### 5.3 扩容规则（1.18+）

- `cap < 256`：翻倍
- `cap >= 256`：增长约 1.25 倍（`newcap += (newcap + 3*256) / 4`）
- 最后按内存分配器的 size class 向上取整，所以**实际容量会比理论值大**

```go
s := make([]int, 0)
for i := 0; i < 10; i++ {
	s = append(s, i)
	fmt.Println(len(s), cap(s))
}
// Go 1.25 / windows-386 实测：
// 1 8 / 2 8 / 3 8 / 4 8 / 5 8 / 6 8 / 7 8 / 8 8 / 9 16 / 10 16
```

> 不要背具体数字（不同版本、不同元素大小结果不同）。记住两件事：**小切片按 size class 取整，大切片按 1.25 倍增长**；以及"预分配能省大量内存"。

**预分配能省大量内存**：已知长度时 `make([]T, 0, n)`。

### 5.4 三个必踩的坑

```go
// 坑 1：append 后忘记接收返回值
s := []int{1}
append(s, 2)          // 编译错误（返回值被丢弃），Go 救了你

// 坑 2：多个切片共享底层数组，互相污染
base := make([]int, 3, 10)
a := base[:2]
a[0] = 9              // base[0] 也变了

// 坑 3：大数组切片导致内存无法释放
func getFirst(big []byte) []byte {
	return big[:1]    // 持有整个 big 的引用，big 无法 GC
}
// 正确：copy 出来
func getFirstOK(big []byte) []byte {
	out := make([]byte, 1)
	copy(out, big)
	return out
}
```

### 5.5 常用操作

```go
s = append(s, x)
s = append(s[:i], s[i+1:]...)          // 删除下标 i（O(n)）
copy(dst, src)                         // 返回拷贝个数
slices.Contains(s, x)                  // Go 1.21+
slices.Index(s, x)
slices.Sort(s)                         // 泛型排序，比 sort.Slice 快
slices.Reverse(s)
slices.Clone(s)                        // 深拷贝（浅拷贝元素）
s2 := slices.Delete(s, 1, 3)
```

## 6. map（D3）

```go
m := make(map[string]int)   // 必须 make
m["a"] = 1
v, ok := m["a"]             // comma-ok：区分"零值"和"不存在"
delete(m, "a")
for k, v := range m { ... } // 遍历顺序随机
```

### 6.1 关键事实

| 事实 | 说明 |
|---|---|
| 并发读写 | **fatal error**，直接崩进程，`recover` 都救不了 → 用 `sync.RWMutex` 或 `sync.Map` |
| 遍历无序 | 每次随机起点，不要依赖顺序 |
| key 必须可比较 | 不能是 slice/map/func；struct 可以（但要全字段可比较） |
| 取地址 | `&m["k"]` 非法，因为值可能被扩容搬移 |
| nil map | 可读（返回零值），写 panic |

### 6.2 用 map 实现集合

```go
set := map[string]struct{}{}
set["a"] = struct{}{}
if _, ok := set["a"]; ok { ... }
```

`struct{}` 不占内存，是 Go 的"空值"惯用法。

### 6.3 并发安全方案

```go
// 方案 A：RWMutex（最常用，读写都有）
type SafeMap struct {
	mu sync.RWMutex
	m  map[string]int
}

func (s *SafeMap) Get(k string) (int, bool) {
	s.mu.RLock()
	defer s.mu.RUnlock()
	v, ok := s.m[k]
	return v, ok
}

// 方案 B：sync.Map（读多写少、key 相对固定，如缓存）
var m sync.Map
m.Store("a", 1)
v, ok := m.Load("a")
m.Range(func(k, v any) bool { return true })
```

> 实测：高频读写场景 `sync.Map` 往往**不如** `RWMutex + map`，别迷信。

## 7. 流程控制（D2）

### 7.1 if / for / switch

```go
if v, err := do(); err == nil { // 支持初始化语句，作用域只在 if 内
	_ = v
} else {
}

// for 是唯一的循环
for i := 0; i < 10; i++ {}
for i < 10 {}                // 只有条件（while）
for {}                       // 死循环
for i, v := range items {}   // 遍历

switch x := f(); x {         // 不必写 break，默认不穿透
case 1:
case 2, 3:                   // 多值匹配
default:
}

// 类型 switch
switch v := anyVal.(type) {
case int:
	fmt.Println("int", v)
case string:
	fmt.Println("string", v)
default:
	fmt.Printf("other %T\n", v)
}
```

### 7.2 标签跳出多层循环

```go
outer:
for i := 0; i < 3; i++ {
	for j := 0; j < 3; j++ {
		if i*j == 2 {
			break outer   // 直接跳出外层
		}
	}
}
```

### 7.3 `defer` 执行顺序与陷阱

```go
func f() {
	for i := 0; i < 3; i++ {
		defer fmt.Println(i) // 参数在 defer 时求值 → 输出 2 1 0（LIFO）
	}
}
```

```go
// 陷阱：defer 在循环里会堆积，直到函数返回才执行
for _, file := range files {
	defer file.Close()   // 1000 个文件 = 1000 个未关闭句柄
}
// 正确：包一层函数
for _, file := range files {
	func() {
		defer file.Close()
		// ...
	}()
}
```

```go
// 陷阱：defer 修改命名返回值
func f() (err error) {
	defer func() {
		if r := recover(); r != nil {
			err = fmt.Errorf("panic: %v", r)
		}
	}()
	panic("boom")
}
```

`recover()` **只在 defer 的函数里、同一个 goroutine 里**有效。

```go
func add(a, b int) int { return a + b }

func divmod(a, b int) (q, r int) { return a / b, a % b }
```

```go
func counter() func() int {

	return func() int { n++; return n }

c := counter()
fmt.Println(c(), c(), c())  // 1 2 3
```

### 8.2 函数作为一等公民

```go
type HandlerFunc func(ctx context.Context, req *Request) (*Response, error)

func WithLogging(next HandlerFunc) HandlerFunc {

	}
}
```

这就是中间件、装饰器模式的 Go 写法。

## 9. 指针（D3）

```go
x := 1
p := &x       // 取地址
*p = 2        // 解引用
fmt.Println(x) // 2
```

什么时候用指针？

| 场景 | 用指针 |
|---|---|
| 修改调用方数据 | ✅ |
| struct 很大（> 几十字节） | ✅ 避免拷贝 |
| 需要表达"可能不存在" | ✅ nil |
| 小结构体、只读 | ❌ 值即可 |
| slice/map/chan/func | ❌ 本身就是引用语义 |

```go
// Go 没有指针运算，比 C 安全得多
// new(T) 返回 *T，指向零值；日常用 &T{} 更直观
p := new(int)      // *int，值为 0
q := &User{Name: "a"}
```

> 记住：**方法接收者用 `*T` 还是 `T`？** 要修改状态、或 struct 大，用 `*T`；其余用 `T`。同一类型的方法集尽量统一。

## 10. 结构体、方法、组合（D4）

```go
type User struct {
	ID        int64     `json:"id" db:"id"`
	Name      string    `json:"name"`
	CreatedAt time.Time `json:"created_at"`
	private   string    // 小写字段不会被 json 序列化
}

func NewUser(name string) *User {
	return &User{Name: name, CreatedAt: time.Now()}
}

func (u *User) Rename(name string) { u.Name = name }
```

### 10.1 嵌入（组合优于继承）

```go
type Base struct{ ID int64 }
func (b Base) Hello() string { return "base" }

type Admin struct {
	Base              // 匿名嵌入：提升字段和方法
	Level int
}
a := Admin{Base: Base{ID: 1}, Level: 9}
fmt.Println(a.ID, a.Hello()) // 1 base
```

嵌入不是继承：`Admin` 不"是" `Base`，但拥有它的字段和方法。

### 10.2 方法集规则（决定接口能否实现）

| 类型 | 方法集 |
|---|---|
| `T` | 只含值接收者方法 |
| `*T` | 值接收者 + 指针接收者方法 |

所以：接口方法若定义在 `*T` 上，只有 `*T` 满足接口，`T` 不满足。

```go
type Speaker interface{ Speak() }
type Dog struct{}
func (d *Dog) Speak() {}
var s Speaker = &Dog{}  // ✅
// var s Speaker = Dog{} // ❌ 编译错误
```

### 10.3 函数式选项（生产代码必备）

```go
type Server struct {
	addr    string
	timeout time.Duration
}

type Option func(*Server)

func WithAddr(a string) Option    { return func(s *Server) { s.addr = a } }
func WithTimeout(d time.Duration) Option { return func(s *Server) { s.timeout = d } }

func NewServer(opts ...Option) *Server {
	s := &Server{addr: ":8080", timeout: 3 * time.Second}
	for _, o := range opts { o(s) }
	return s
}
```

## 11. 接口（D4）

```go
type Reader interface{ Read(p []byte) (n int, err error) }

// 隐式实现：不需要 implements 关键字
type MyReader struct{}
func (m MyReader) Read(p []byte) (int, error) { return 0, io.EOF }
var _ io.Reader = MyReader{}   // 编译期断言，工程里常用
```

### 11.1 类型断言

```go
var x any = "hello"
s, ok := x.(string)   // 安全
n := x.(int)          // 不安全：断言失败 panic
```

### 11.2 空接口与 `any`

`any` = `interface{}`。它丢失类型信息，用之前必须断言。**不要滥用**，能用泛型就用泛型。

### 11.3 nil 接口陷阱（必考）

```go
type MyErr struct{}
func (e *MyErr) Error() string { return "my" }

func do() error {
	var e *MyErr = nil
	return e           // ❌ 返回的 error 非 nil！
}

func main() {
	if err := do(); err != nil {
		fmt.Println("err != nil")  // 会打印
	}
}
```

原因：`error` 是接口（type, value）二元组，`(*MyErr)(nil)` 的 type 非空，所以接口 != nil。

> 规则：**返回 error 时，失败就 `return nil`，不要返回带类型的 nil 指针。**

### 11.4 接口设计原则

- **接口由使用方定义，越窄越好。** 标准库大量单方法接口：`io.Reader`、`io.Writer`、`fmt.Stringer`。
- **不要在实现方提前定义大接口。** 先写具体类型，等调用方需要抽象时再抽接口。
- 返回具体类型，接受接口。

```go
// 好
func NewService(repo UserRepo) *Service
// 差
func NewService(repo any) *Service
```

## 12. 错误处理（D5）

Go 的错误是值，不是异常。

```go
func ReadConfig(path string) (*Config, error) {
	data, err := os.ReadFile(path)
	if err != nil {
		return nil, fmt.Errorf("read config %s: %w", path, err)
	}
	var c Config
	if err := json.Unmarshal(data, &c); err != nil {
		return nil, fmt.Errorf("parse config: %w", err)
	}
	return &c, nil
}
```

### 12.1 `%w` / `errors.Is` / `errors.As`

```go
var ErrNotFound = errors.New("not found")

func find(id int) error {
	return fmt.Errorf("query user %d: %w", id, ErrNotFound) // %w 建立错误链
}

err := find(1)
errors.Is(err, ErrNotFound)      // true：沿链比较
var pe *fs.PathError
errors.As(err, &pe)              // true：沿链提取类型
```

### 12.2 自定义错误

```go
type ValidationError struct {
	Field string
	Msg   string
}

func (e *ValidationError) Error() string {
	return fmt.Sprintf("field %s invalid: %s", e.Field, e.Msg)
}

// 使用
var ve *ValidationError
if errors.As(err, &ve) {
	fmt.Println(ve.Field)
}
```

### 12.3 panic 的边界

| 场景 | 用什么 |
|---|---|
| 可预期的失败（IO、校验、下游错误） | `error` |
| 编程错误（越界、nil、不可能的分支） | `panic` |
| 库的初始化失败 | `panic` 或返回 error |
| HTTP handler 崩溃 | 中间件 `recover` 兜底 |

```go
// 顶层兜底，防止单个请求打挂整个进程
func Recover(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		defer func() {
			if rec := recover(); rec != nil {
				log.Printf("panic: %v\n%s", rec, debug.Stack())
				http.Error(w, "internal error", 500)
			}
		}()
		next.ServeHTTP(w, r)
	})
}
```

## 13. 泛型（D5）

Go 1.18 引入。**用得克制**：容器、工具函数、算法库适合；业务代码通常不需要。

```go
// 泛型函数
func Map[T, U any](in []T, f func(T) U) []U {
	out := make([]U, 0, len(in))
	for _, v := range in { out = append(out, f(v)) }
	return out
}

// 约束
type Number interface {
	~int | ~int64 | ~float64   // ~ 表示底层类型也匹配
}

func Sum[T Number](nums []T) T {
	var total T
	for _, n := range nums { total += n }
	return total
}

// 泛型类型
type Stack[T any] struct{ items []T }
func (s *Stack[T]) Push(v T) { s.items = append(s.items, v) }
func (s *Stack[T]) Pop() (T, bool) {
	var zero T
	if len(s.items) == 0 { return zero, false }
	v := s.items[len(s.items)-1]
	s.items = s.items[:len(s.items)-1]
	return v, true
}
```

常用约束：`any`、`comparable`、`cmp.Ordered`（`slices` 包里用）。

> 不要为了泛型而泛型。Go 社区共识：**接口用于行为抽象，泛型用于类型抽象。**

### 14.3 encoding/json

```go

	ID      int64     `json:"id"`
```

## 19. D7 周项目：GoScan v0（单协程版）

**需求**：遍历目录，统计每种扩展名的文件数和总大小，输出 Top 10 大文件。

```go
// 提示骨架，自己补全
func walk(root string) (map[string]int, error) {
	stats := map[string]int{}
	err := filepath.WalkDir(root, func(path string, d fs.DirEntry, err error) error {
		if err != nil { return err }
		if d.IsDir() { return nil }
		ext := strings.ToLower(filepath.Ext(path))
		stats[ext]++
		return nil
	})
	return stats, err
}
```

验收：
- [ ] 能处理权限错误不中断
- [ ] 结果按文件数排序输出
- [ ] 有表格测试
- [ ] 用 `go vet` 无告警

D14 会把它改造成并发版（限流、超时、优雅退出）。
